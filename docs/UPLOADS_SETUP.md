# Cloudinary uploads — one-time setup

The mobile app uploads photos **directly to Cloudinary** using short-lived
signatures generated by `rent95-api`. The file bytes never touch our
server, which saves bandwidth and gives us a real progress bar.

Applied **after** `flutter create --platforms=android,ios .` and after
applying the backend patches in `backend-patches/`.

---

## 1. Create a Cloudinary account (5 minutes)

1. <https://cloudinary.com/users/register_free>
2. Note the three values on your dashboard:
   - **Cloud name** (e.g. `rent95-prod`)
   - **API Key**
   - **API Secret**  ⚠️ Server-side only, never commit or send to a client

## 2. Backend

Apply the two patch files:

```bash
# From your rent95-api checkout
cp /path/to/Rent95/backend-patches/uploads.controller.ts src/controllers/
cp /path/to/Rent95/backend-patches/uploads.routes.ts     src/routes/
npm install cloudinary
```

Then in `src/app.ts`:

```ts
import uploadsRoutes from './routes/uploads.routes';
app.use('/api/uploads', uploadsRoutes);
```

Set your `.env` (the keys are already listed in `.env.example`):

```env
CLOUDINARY_CLOUD_NAME=rent95-prod
CLOUDINARY_API_KEY=123456789012345
CLOUDINARY_API_SECRET=abcdef…       # NEVER commit
```

Smoke test:

```bash
# Grab a token
TOKEN=$(curl -s -X POST http://localhost:4000/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"alex@example.com","password":"demo1234"}' | jq -r .data.accessToken)

# Request a signature
curl -s -X POST http://localhost:4000/api/uploads/signature \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"purpose":"listing"}' | jq
```

Expected output:

```json
{
  "success": true,
  "data": {
    "signature": "…",
    "timestamp": 1735312800,
    "folder": "products/<userId>",
    "publicId": null,
    "apiKey": "123456789012345",
    "cloudName": "rent95-prod",
    "uploadUrl": "https://api.cloudinary.com/v1_1/rent95-prod/image/upload"
  }
}
```

## 3. Flutter — no code changes needed

Everything is wired already. In real mode the app hits
`/api/uploads/signature` and then POSTs directly to Cloudinary. In mock mode
(`USE_MOCKS=true`) the picker still opens but the uploader returns a random
Unsplash URL so the create-listing flow keeps working with zero setup.

## 4. iOS — `ios/Runner/Info.plist`

`image_picker` needs three usage descriptions or iOS crashes with a hard
opaque error the moment the picker opens. Add these inside `<dict>`:

```xml
<key>NSPhotoLibraryUsageDescription</key>
<string>Rent95 needs access to your photos so you can add pictures to your listings.</string>

<key>NSCameraUsageDescription</key>
<string>Rent95 needs your camera so you can take a photo of what you're listing.</string>

<key>NSMicrophoneUsageDescription</key>
<string>Rent95 needs microphone access for video listings (future).</string>
```

## 5. Android — no manifest changes for Android 13+

`image_picker` uses the [Photo Picker](https://developer.android.com/training/data-storage/shared/photopicker)
system UI on Android 13+ which doesn't require any storage permission at
all. For the camera source you need:

```xml
<!-- android/app/src/main/AndroidManifest.xml -->
<uses-permission android:name="android.permission.CAMERA"/>
```

Older Android versions (< 13) need `READ_MEDIA_IMAGES` too, which
`image_picker` already declares transitively.

## 6. `image_cropper` — Android

Add to `android/app/src/main/AndroidManifest.xml` inside `<application>`:

```xml
<activity
    android:name="com.yalantis.ucrop.UCropActivity"
    android:screenOrientation="portrait"
    android:theme="@style/Theme.AppCompat.Light.NoActionBar" />
```

The `image_cropper` plugin uses the uCrop library. Without this activity
declaration the crop screen won't open.

## 7. Test the round-trip

1. `flutter run --dart-define=USE_MOCKS=false --dart-define=API_BASE_URL=http://10.0.2.2:4000`
2. Log in as a seller.
3. Home → **+** (Sell) → step through to the Photos step.
4. Tap **Add photo** → pick from library.
5. Crop → tap done.
6. Watch the progress ring animate, then the thumbnail replaces it.
7. Check the Cloudinary console — the file lands under
   `products/<userId>/…` with a `secure_url` your listing detail
   screen can render straight away.

## 8. Cloudinary → thumbnails via URL

We never make a second API call for thumbnails — Cloudinary does that
lazily. `UploadedMedia.thumbnailUrl(width: 400)` splices
`w_400,c_fill,g_auto,f_auto,q_auto` into the `secure_url` between
`/upload/` and the version segment. First fetch renders the derivative,
Cloudinary CDN caches it forever.

## 9. Cleanup on listing delete (v1.1)

For MVP we leak orphan Cloudinary assets when a listing is deleted — the
Cloudinary free tier is generous enough that this doesn't matter. For v1.1,
add a `cloudinary.uploader.destroy(publicId)` call in the backend's product
delete path. Track `publicId` alongside the URL on the `product_media` row.

## 10. Signed vs. unsigned uploads

We use signed uploads (backend generates a signature) rather than unsigned
uploads (client picks a preset). Signed:

- ✅ Backend controls the folder → users can't dump into each other's namespace
- ✅ Backend can enforce moderation, size caps, allowed formats via
  transformations in the signature
- ✅ Rotating the API secret invalidates every in-flight upload
- ⚠️ One extra network hop per file (the signature request)

The alternative — unsigned uploads with a preset — is faster to set up but
means a compromised client can upload arbitrary files to your account.
Worth it for a marketplace where a seller's device is untrusted by design.
