# Stripe setup — one-time platform config

`flutter_stripe` needs a couple of platform-side tweaks that live in the
`android/` and `ios/` folders. Because this repo ships without those folders
(they're regenerated by `flutter create .`), apply the changes below the
**first time** you run `flutter create`. Commit the results — they're
platform boilerplate, not secrets.

---

## 1. Environment variables

At runtime the app reads:

| Variable | Where | Notes |
|---|---|---|
| `STRIPE_PUBLISHABLE_KEY` | `--dart-define` | Test key: `pk_test_…`, live key: `pk_live_…`. Never commit. |

The backend also needs `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, and
`STRIPE_CONNECT_CLIENT_ID` — see `rent95-api/.env.example`.

Run the app in real-Stripe mode with:

```bash
flutter run \
  --dart-define=USE_MOCKS=false \
  --dart-define=API_BASE_URL=http://10.0.2.2:4000 \
  --dart-define=STRIPE_PUBLISHABLE_KEY=pk_test_xxx
```

Leave `STRIPE_PUBLISHABLE_KEY` unset for a graceful no-op — the checkout
still works via the mock happy-path so demos and tests keep running.

---

## 2. Android — `android/app/build.gradle`

Stripe's Android SDK requires **minSdkVersion 21** and Kotlin ≥ 1.8. If
you generated the project with a newer Flutter (3.24+) these are already fine,
but double-check:

```gradle
android {
    defaultConfig {
        minSdkVersion 21   // Stripe requirement
        // …
    }
}
```

## 3. Android — `android/app/src/main/AndroidManifest.xml`

Google Pay needs a metadata flag. Add inside `<application>`:

```xml
<meta-data
    android:name="com.google.android.gms.wallet.api.enabled"
    android:value="true" />
```

## 4. iOS — `ios/Runner/Info.plist`

Add the following inside the top-level `<dict>`:

```xml
<!-- 3-D Secure redirect scheme. Must match Stripe.urlScheme in stripe_service.dart. -->
<key>CFBundleURLTypes</key>
<array>
    <dict>
        <key>CFBundleTypeRole</key>
        <string>Editor</string>
        <key>CFBundleURLSchemes</key>
        <array>
            <string>rent95</string>
        </array>
    </dict>
</array>
```

## 5. iOS — Apple Pay entitlement (optional but recommended)

If you want the "Pay with Apple Pay" button to appear inside the sheet:

1. Open `ios/Runner.xcworkspace` in Xcode.
2. Runner target → **Signing & Capabilities** → **+ Capability** → **Apple Pay**.
3. Add your merchant identifier (`merchant.dev.rent95` is the value hard-coded
   in `stripe_service.dart`; change both together if you use a different one).
4. Enroll the identifier at
   [developer.apple.com/account/resources/identifiers](https://developer.apple.com/account/resources/identifiers/list/merchant).

Without this, Apple Pay is silently omitted from the sheet — cards still work.

## 6. iOS — minimum deployment target

Stripe's iOS SDK needs **iOS 13+**. In `ios/Podfile`:

```ruby
platform :ios, '13.0'
```

## 7. Test cards

Once everything is wired, use these Stripe test cards inside the sheet
(any future expiry, any 3-digit CVC):

| Card | Outcome |
|---|---|
| `4242 4242 4242 4242` | Success |
| `4000 0025 0000 3155` | Requires 3-D Secure authentication |
| `4000 0000 0000 9995` | Declined (insufficient funds) |
| `4000 0000 0000 0002` | Declined (generic) |

Full list: <https://docs.stripe.com/testing>.

## Verifying the wire

1. Buyer taps **Pay $X** in the app.
2. Client sends `POST /api/payments/create-intent { orderId }` — backend creates
   a PaymentIntent with `capture_method: 'manual'` and `application_fee_amount`.
3. Client receives `{ clientSecret, paymentIntentId }`.
4. `StripeService.presentPaymentSheet` initialises + presents.
5. User completes the card entry.
6. Stripe sends a `payment_intent.amount_capturable_updated` webhook to the
   backend, which flips `orders.status → paid` and `payments.status → authorized`.
7. Client's socket receives an `order_updated` event and refreshes the order
   detail screen automatically.
8. Funds stay held (escrow) until the order transitions to `completed`, at
   which point the backend captures and marks the payout eligible.

To watch webhooks locally during development:

```bash
stripe listen --forward-to localhost:4000/api/payments/webhook/stripe
```

The CLI prints a `whsec_…` secret — set that as `STRIPE_WEBHOOK_SECRET` in
`rent95-api/.env`.
